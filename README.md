# FY175AutoMosaic

Windows上でPNG/JPEG画像をまとめて確認し、検出した対象へモザイクまたは
ぼかしを適用するデスクトップアプリです。画像は外部へ送信されず、すべて
ローカルで処理されます。

## できること

- PNG/JPEG画像を複数まとめて、またはドラッグ＆ドロップで読み込み
- 実写／イラストを切り替え、対象を自動検出
- 検出範囲と処理後の画像を保存前にプレビュー
- 選択ブラシで検出マスクの不足部分を追加し、余分な部分を削除
- Shift+クリックによるAI領域選択と、Ctrl+Zによるマスク編集の取り消し
- モザイク／ぼかしの種類、強さ、検出しやすさを調整
- マスク閾値・拡張・滑らかさで、自動マスクの範囲と輪郭を調整
- モザイク／ぼかし処理した画像を指定フォルダへ保存
- PNGの加工保存時に、元画像の生成プロンプトやワークフロー等のテキストメタデータ（tEXt／iTXt／zTXt）を保持
- 元画像の隣の `.fy` テキストファイルにマスクと設定を保存し、次回の読み込みで復元
- 自動処理から除外した画像名を、要手動対応メモとして管理
- エージェント向けのローカルHTTP APIから画像の読み込み・マスク編集・保存を操作
- 別ウィンドウの動画モードで全フレームを解析し、マスク数のタイムラインを確認してMP4へ書き出し

## 起動方法

### Windows配布版を使う場合

1. 配布されたZIPを展開します。
2. `FY175AutoMosaic`フォルダ内の`FY175AutoMosaic.exe`を起動します。

`FY175AutoMosaic.exe`だけを別の場所へ移動しないでください。モデルや動作に必要な
ファイルを含むため、展開した`FY175AutoMosaic`フォルダ全体をそのまま使用します。

### ソースコードから起動する場合

Python 3.13をインストールし、リポジトリを取得したフォルダでPowerShellを
開いて、次のコマンドを順番に実行します。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe scripts\download_models.py
.\.venv\Scripts\python.exe -m auto_mosaic.app
```

`download_models.py`が必要なモデルを自動で`models`フォルダへ配置し、ファイルが
正しいかも確認します。ダウンロードにはインターネット接続と約170MB以上の
空き容量が必要です。

NudeNetはパッケージをインストールせず、固定バージョンの配布ファイルからモデルだけを
取り出し、配布ファイルとモデルのSHA-256を確認します。

正常に配置されるファイルは次の4つです。

- `models/nudenet-320n.onnx`
- `models/anime-censor-detect-v1.0-n.onnx`
- `models/sam2_hiera_tiny.encoder.onnx`
- `models/sam2_hiera_tiny.decoder.onnx`

モデル不足のメッセージが表示された場合は、リポジトリ直下で
`.\.venv\Scripts\python.exe scripts\download_models.py`をもう一度実行してください。
モデルの出典とライセンスは`MODEL_LICENSES.md`に記載しています。

### NVIDIA GPUで高速化する場合

CUDA対応のNVIDIA GPUでは、対象検出とSAM2によるマスク生成をGPUで実行できます。
画像・動画・Shift+クリックのAI領域選択に共通で適用されます。
ソース版のセットアップは次のとおりです。

```powershell
.\scripts\setup.ps1 -Gpu
.\.venv\Scripts\python.exe -m auto_mosaic.app
```

GPU用の依存関係は `requirements-gpu.txt` に固定しています。CUDA 13対応ドライバーが必要です。
CUDA/cuDNNのDLLは仮想環境へ導入するため、CUDA Toolkitの別途インストールは不要です。
CPU版とGPU版のONNX Runtimeは同じモジュールを使うため、同時にインストールしないでください。
`setup.ps1` は競合する版を取り除きます。CPU版へ戻す場合は `setup.ps1` を引数なしで実行します。

通常はGPUを自動選択し、利用できない場合はCPUで動作します。明示的に指定する場合は
起動前に `$env:AUTO_MOSAIC_DEVICE = 'cpu'` または `'cuda'` を設定します。
`'cuda'` 指定ではGPUを初期化できないとエラーになるため、CPUへの切替を見逃さず確認できます。
`Remove-Item Env:AUTO_MOSAIC_DEVICE` で自動選択へ戻ります。

ローカルのGPU対応EXEは `.\scripts\build.ps1 -Gpu` で作成します。既存のCPU版EXEは
仮想環境の更新だけではGPU対応になりません。GPUビルドはCUDA/cuDNNのDLLも含むため容量が増えます。
再配布前の確認事項は `DISTRIBUTION.md` を参照してください。

速度比較は次のコマンドで、CPU/GPUに同じ合成画像を渡して実行できます。

```powershell
.\.venv\Scripts\python.exe -m scripts.benchmark_inference --output .codex-qa\gpu\benchmark.json
```

モデル初期化を除き、ウォームアップ後の5回を測定し、利用プロバイダーとマスクの差も記録します。
実画像の精度評価ではありません。読み込み、モザイク処理、動画の圧縮などは引き続きCPU処理です。
GPU実装は [ONNX RuntimeのCUDA仕様](https://onnxruntime.ai/docs/execution-providers/CUDA-ExecutionProvider.html)に従います。

### エージェントから操作する場合

エージェント向けのローカルHTTP APIを内蔵しています。`--agent-api` を付けて起動し、
ルートURLへGETすると、操作一覧・引数・設定範囲・操作手順を取得できます。

配布版では、展開した `FY175AutoMosaic` フォルダでPowerShellを開いて起動します。

```powershell
.\FY175AutoMosaic.exe --agent-api
```

起動後、別のPowerShellから案内を取得できます。

```powershell
Invoke-RestMethod -Uri 'http://127.0.0.1:8765/' -Method Get
```

ソース版は `.\.venv\Scripts\python.exe -m auto_mosaic.app --agent-api` で起動します。
ポートを変える場合は `--agent-api 8766` のように指定します。通常起動ではAPIを開きません。
外部サービスやMCP登録は不要で、画像は外部へ送信されません。

エージェントには「`http://127.0.0.1:8765/` にGETし、返された操作一覧と手順に従って
画像を処理する」と伝えます。APIは画面と同じ画像リスト・設定・マスク編集状態を使います。

| リクエスト | 用途 |
| --- | --- |
| `GET /` | 操作一覧、引数、設定範囲、操作手順、アプリのPIDを取得 |
| `GET /state` | 選択画像、マスク、処理状態を確認 |
| `GET /preview?view=mask_overlay` | マスク範囲のプレビューを取得 |
| `POST /commands` | 画像の読み込み、設定変更、マスク編集、保存などを実行 |
| `GET /jobs/ID` | 非同期処理の完了・失敗を確認 |

`POST /commands` には `{"operation":"操作名","arguments":{...}}` を送ります。
非同期処理は返されたジョブが `succeeded` または `failed` になるまで確認してください。
`.fy` の保存・復元も操作でき、終了には `app.shutdown` を使います。
具体的な操作と座標の扱いは、同梱の [AGENT_INTERFACE.md](AGENT_INTERFACE.md) を参照してください。


## 基本的な使い方

1. 処理する画像を読み込みます。
2. 画像に合わせて「実写」または「イラスト」を選びます。
3. 「詳細設定…」で画像の種類、検出対象、検出閾値を指定します。開いたまま本体も操作できます。
4. プレビューで検出範囲と処理結果を確認します。
   どの表示でもマウスホイールで画像を段階的に拡大・縮小できます。画像上では
   カーソル位置、それ以外では画像中央が基準になり、初期表示より小さくはなりません。
5. 必要なら、どのプレビュー表示からでも「マスクを編集」を開始できます。
   詳しい操作は下の「マスク編集の操作」を参照してください。
6. 出力先を選び、「表示中の1枚を処理して保存」または「すべて処理して保存」で保存します。

初回の画像表示時はモデルの読み込みに少し時間がかかることがあります。

### マスク編集の操作

「マスクを編集」を押してから、画像上で次の操作を行います。「元画像」「処理結果」から
編集を開始すると「マスク範囲」表示へ切り替わり、検出矩形とラベルは非表示になります。

| 操作 | 動作 |
| --- | --- |
| ドラッグ | ブラシでマスク範囲を追加 |
| Alt+ドラッグ | ブラシでマスク範囲を削除 |
| Shift+クリック | クリック位置のAI推定領域を追加 |
| Ctrl+Shift+クリック | クリック位置のAI推定領域を削除 |
| Ctrl+Z | 直前のマスク編集を取り消し |
| マウスホイール | カーソル位置を基準に段階的に拡大・縮小 |

AI領域選択は現在の「マスク閾値」を使い、クリック位置につながる部分だけを選びます。
色差による選択ではありません。初回のクリックでは画像の解析に時間がかかる場合があります。
選択範囲が合わない場合は閾値を調整して再度クリックするか、ブラシで補います。

Ctrl+Zでは、1ドラッグまたは1回の領域選択が1操作です。履歴はAPI操作と共通で
最大20操作（圧縮マスク合計128 MiB以内）を保持し、保存・編集終了・画像切替で消去します。
編集中に「処理結果」へ切り替えても編集内容は保持されるため、仕上がりを確認してから保存できます。

編集したマスクは「表示中の1枚を処理して保存」でのみ使用され、画像を切り替えたり
リストから除去したりする際は、未保存の編集を破棄するか確認します。
編集内容を後で使う場合は「.fy保存」を有効にして保存してください。

### .fyファイルにマスクと設定を保存・復元する

`.fy` はマスク範囲と処理設定を記録するファイルです。画像そのものは含まず、
処理後の画像とは別に、**元画像の隣**へ保存します。

「処理後にリストから除去」の隣の「.fy保存」を有効にすると、処理して保存する際に、元画像と同じ
フォルダへ `画像.png.fy`（JPEGなら `画像.jpg.fy`）を保存します。一括処理も対象です。
既存の `.fy` は最新の内容で更新します。「処理せず保存」では `.fy` を保存しません。

例えば、`C:\images\sample.png` を読み込み、マスクを編集して「.fy保存」を有効にして
処理すると、`C:\images\sample.png.fy` が作成されます。次回は処理後の画像ではなく、
同じ元画像 `sample.png` を読み込むとマスクと設定を復元できます。

元画像を再び読み込むと、隣の `.fy` からマスク範囲と処理設定を自動復元します。
上部の「マスク復元」でも読み込み直せます。元画像の隣に対応する `.fy` があればすぐに復元し、
なければファイル選択画面を開きます。別の場所へ移した `.fy` も選択できますが、元画像は保存時と同じものが必要です。
未保存のマスク編集中は置き換え前に確認し、読み込みエラーやファイル選択のキャンセルでは編集内容を保持します。
モザイク／ぼかしの種類やサイズを変更してもマスク範囲を保持し、再解析せずに保存できます。
一括処理では保存済みのマスクと現在の画面の設定を使います。「この画像を再解析」を押すと
自動検出からやり直します。再解析や編集中の範囲を残す場合は、改めて `.fy` を保存してください。

`.fy` はUTF-8のJSONテキストで、画像寸法、元画像のSHA256、処理設定、正確なピクセル範囲を
連続区間の開始位置と長さで記録します。元画像が変わっていたりファイルが壊れていたりする場合は
エラーを表示し、保存済み範囲を黙って自動検出で置き換えません。移動時は元画像と `.fy` を一緒に移動してください。

### 検出対象は正しいのにマスク範囲が合わない場合

「詳細設定…」の「マスク閾値」「マスク拡張」「マスクの滑らかさ」を調整し、「この画像を再解析」を押します。

- **マスクの滑らかさ**（初期値 `0 px`、範囲 `0` ～ `20 px`）：`0` で無効です。大きくすると細かな凹凸を丸めます。元画像のピクセル単位で、拡張より先に適用します。輪郭が内外に動くため、再解析後にマスク範囲を確認してください。ぼかし効果や境界の半透明化ではありません。手動マスクと矩形補完には適用しません。

「検出範囲」表示で輪郭を確認し、「処理結果」表示で仕上がりを確認してください。

- **マスク閾値**（初期値 `0.0`、範囲 `-10.0` ～ `10.0`）：各ピクセルをマスクへ含める判定値です。
  隣の領域を巻き込む場合は上げ、対象の一部しか選ばれない場合は下げて、まず `0.5` 刻みで試します。
  対象そのものの採否を決める「検出閾値」とは別の設定です。
- **マスク拡張**（初期値 `3 px`、範囲 `0` ～ `20 px`）：判定後の輪郭の周囲を広げる量です。
  元画像のピクセル単位です。周辺を巻き込む場合は `0 px` まで減らせます。
  細い隙間や凹みを埋める輪郭補正は拡張量から独立しており、`0 px` でも一定の強さで行います。
  `0 px` は輪郭補正後のマスクを周囲へ広げない設定です。突出部分を削る処理ではありません。

値を変えるだけでは表示中のマスクは変わりません。自動マスクには次の解析・保存処理から適用されます。
設定は実写／イラストと単一画像／一括処理で共通です。`.fy` に保存した設定は元画像の読み込み時に復元されます。
編集中もマスク閾値は変更でき、次のクリックによる領域選択に反映します。
マスク拡張・滑らかさは編集中に変更できません。クリックによる領域選択には拡張・滑らかさを適用せず、
編集したマスクの保存にも閾値・拡張・滑らかさを再適用しません。

滑らかさの項目がない旧形式の `.fy` / `.fyvideo` には対応していません。

閾値を変えると別の輪郭候補が選ばれることもあり、常に少しずつ広がる・狭まるとは限りません。
また、検出枠付近への制限と中心付近の領域だけを残す処理があるため、閾値だけでは補えない不足もあります。
「矩形補完」と表示された対象は輪郭候補が採用できず検出矩形で代用しており、マスク閾値や拡張による
輪郭調整は効きません。改善しない場合は「マスクを編集」で追加・削除してください。

## 動画モード

静止画画面の上部にある **「動画モード(β)」** ボタンから専用ウィンドウを開きます。
静止画の選択・マスク編集・ズームは保持されます。
ソースから直接起動する場合は `python -m auto_mosaic.app --video` も使えます。

1. 「動画を開く」またはドラッグ＆ドロップで、MP4 / MOV / MKV / WebM / AVI / M4Vを読み込みます。
2. 「詳細設定…」で「実写／イラスト」、検出対象、閾値、輪郭更新の間隔、マスクの滑らかさを設定して「動画を解析」を押します。詳細設定を開いたまま本体を操作できます。
3. 青いグラフ（左軸）で検出マスク数、ピンクの折れ線（右軸）で検出面積の割合を確認します。見出し行の「数」「面積」で個別に表示を切り替えられ、初期状態は両方オンです。0件の区間と短い減少は橙色で示します。タイムライン上のホイールでマウス位置を基準に拡大・縮小できます。
   グラフのクリック、フレーム送り、変化点一覧、「前／次の変化点」でプレビューを移動できます。
   「全体／10秒／1秒」で拡大でき、1フレームの途切れも記録されます。
4. 「元画像／検出範囲／処理結果」を切り替えて確認し、処理方法とサイズを調整します。
   プレビューは最大960pxの確認用画像による無音再生です。
5. 「動画を書き出す…」で新しいMP4ファイルへ保存します。既存ファイルは上書きしません。

解析完了までは書き出せません。検出設定を変えると再解析が必要です。
モザイク／ぼかしとサイズだけを変えた場合は、解析済みマスクをそのまま利用できます。
マスク数は閾値を超えた対象数（矩形代替を含む）で、重なった領域も別々に数えます。
検出面積は元の解析マスクが画面全体に占める割合（%）で、重なりは一度だけ数えます。手動編集・補完では変化しません。
0件は検出がなかったことを示し、対象が存在しないことを保証するものではありません。

### 動画のマスク編集と自動補完

解析後は動画画面内のどこにフォーカスがあっても、左右キーで1フレームずつ移動できます。
マスク編集中の変更は移動前に現在のフレームへ適用し、移動先でも編集を続けられます。
処理中は移動を待ち、ファイル選択などの別ダイアログでは通常のキー操作になります。

1. 解析後、編集したいフレームに移動し、右側の「マスク編集」タブを開きます。
2. 「マスクを編集」を押します。静止画と同じくドラッグで追加、Alt＋ドラッグで削除します。
   ブラシは元動画のピクセル単位です。ホイールでカーソル位置を中心に拡大・縮小できます。
   編集中も「元画像／検出範囲／処理結果」を切り替えられます。
3. 「このフレームに適用」で確定します。このフレームが補完の始点になります。
   自動検出できているフレームを使う場合、編集せず「現在位置を始点にする」を押せます。
4. タイムラインで補完したい最後のフレームへ移動します。黄色の点・破線が始点、黄色の帯が補完予定範囲です。
   表示範囲外の始点は端のマーカーと矢印付きフレーム番号で示します。
5. 「補完」で、始点の次から現在のフレームを含む範囲へマスクを動きに追従させます。
   結果を確認し、必要なら「直前のマスク変更を戻す」で最後の適用／補完を取り消せます。
6. 補完範囲を確認してから「動画を書き出す…」で保存します。

タイムライン上端の緑が手動編集・補完した範囲です。青いグラフの検出数は元の解析結果を保持します。
補完したマスクは各フレームの既存マスクへ追加し、始点で手動削除した領域も追従して除きます。
別の対象の自動検出は残します。範囲内に別の手動編集済みフレームがある場合は、補完ボタンを無効にし、対象のフレーム番号を表示します。
「このフレームの修正を解除」で現在のフレームを、「補完範囲の修正を解除」で黄色の帯の範囲を元の自動検出結果に戻せます。
範囲の解除では始点は変更しません。解除も「直前のマスク変更を戻す」で取り消せます。

追従にはキャッシュ済みの最大960pxの画像とオプティカルフローを利用し、再検出・再推論は行いません。
編集マスク自体は元解像度で保存します。細かい動き、急な変形、遮蔽ではずれることがあるため、短い区間で確認してください。
シーン変化や追従不安定を検出した場合、中止した場合、エラーが起きた場合は補完範囲全体を反映しません。
検出できないずれもあるため、自動補完の成功はマスクの正確さを保証しません。

### 動画の編集を保存・再開する

動画画面の Ctrl+S は「編集を保存…」ボタンと同じ動作です。保存先を選んで .fyvideo に保存します。

解析後、上部の「編集を保存…」で `.fyvideo` ファイルへ保存できます。
解析結果、検出座標、手動編集・補完済みマスク、直前のマスク変更を戻す履歴、処理設定、
現在のフレーム、表示モード、タイムラインの表示範囲、補完の始点、ブラシサイズを保存します。補完の終点は現在のフレームです。
動画編集形式はバージョン2です。旧形式からの移行には対応していません。
「このフレームに適用」前の編集中マスクも保存・復元します。復元後に適用してから動画を書き出してください。

「編集を開く…」で再読み込みすると、再解析せずに続きから編集・書き出しできます。
復元位置は最後に保存した時点です。未保存のマスク・処理設定の変更はタイトル末尾の `*` で示し、
動画切替・再解析・画面終了前に確認します。動画を書き出しても編集プロジェクトは自動保存されません。

`.fyvideo` は確認用画像を含むため、長い動画ほど容量が増えます。元動画そのものは含まないため、
元動画も保管してください。元動画を移動した場合、編集ファイルと同じフォルダの同名動画、保存時のパスの順に探し、
見つからなければ元動画を選択する画面を開きます。SHA256で保存時と同じ内容か照合し、異なる動画には適用しません。
保存失敗・中止では前回の保存ファイルを保持し、読み込み失敗・中止では現在の編集を保持します。

### 処理速度と保存形式

- 検出は全フレームで行います。「毎フレーム」が標準です。
  高速設定では3または5フレームごとに輪郭を計算し、間の輪郭は検出矩形に合わせて移動・拡縮します。
  新しい対象、追跡失敗、大きな場面変化では再計算します。変形や遮蔽には遅れる場合があります。
- 解析済みマスクと確認用画像はローカルの一時キャッシュへ圧縮保存します。
  書き出し時の再推論は不要です。長い動画ほど一時ディスク容量を使います。
  動画切替・再解析・画面終了で不要なキャッシュを削除します。
- 出力はH.264（CRF 18）、先頭の音声トラックはAAC 192kbpsです。無音動画も処理できます。
  プレビューと出力を一致させるため、可変fps入力は解析・出力とも元動画の平均fpsで固定fps化します。
  縦動画の回転情報を反映し、奇数寸法は右端／下端に最大1pxを足します。
- HDR、非正方形ピクセル、240fps超の入力は未対応です。字幕と2本目以降の音声は出力しません。
- 推論は既存のCPU版ONNX Runtimeを使用します。GPU用依存ライブラリは追加していません。
  動画入力と音声処理は [FFmpeg](https://ffmpeg.org/ffmpeg.html) を使用します。

ソース実行は `auto_mosaic/video_io.py` の `SHARED_FFMPEG_DIR` にある共有FFmpegを使います。
この環境では `C:\Users\Admin\.codex\tools\ffmpeg\bin` です。配布版は同梱の実行ファイルを使います。
`scripts/build.ps1` は同じ設定元からFFmpegとffprobeを取得して同梱します。
既存環境での再ビルドは `scripts/build.ps1 -UseExistingEnvironment` で依存の再取得を省けます。
